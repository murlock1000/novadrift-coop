# Development

Run tools from WSL with native Windows interop. See [installation](INSTALLATION.md)
for the exact supported game build and toolchains. Setup verifies the pristine executable SHA:
`6555f9f49c9b44f2a38dafc0846dd8af0e7e1f1e100cba976db60967b7173e2d`.

```sh
python3 tools/fetch_dependencies.py
python3 tools/fetch_dependencies.py --verify-only
python3 tools/build_native.py
python3 tools/build_ship_config.py
```

Build the ship DLL from Windows CMD using `tools\build_ship.cmd`; or invoke that
script through PowerShell from WSL, since `pushd` inside it handles the UNC path.
Then, with the owned game/helper closed:

```sh
python3 tools/prepare_ships.py
python3 tools/prepare_remoteplay.py --stage
```

`prepare_ships.py` requires the pristine `game/` copy and private original-save
baseline generated by `setup_project.py`. It patches a fresh owned EXE with Aurie;
Aurie embeds the absolute loader path, so rerun staging after moving the install.
`local/active-runtime.json` records the active install. Do not copy a patched
executable into the original Steam game folder.

## Source map

| Files | Responsibility |
|---|---|
| `src/coop_ship.cpp`, `ship_*.hpp` | Native player ownership, hooks, independent builds/upgrades, input, lifecycle and native HUD |
| `src/launch.cpp`, `sandbox.cpp` | Owned process launch, display preference handling, isolated profile and Steam API interception |
| `src/steam_coop.cpp` | Spacewar launch-option wrapper, setup UI and process lifetime |
| `src/ship_config_tool.cpp`, `ship_config.hpp` | P2 bindings and editor |
| `src/ship_balance*.hpp` | Configurable co-op arena, native hostile attention, regular spawn budgets, XP and isolated trait grants |
| `src/native_abi.hpp`, `ship_signatures.hpp` | Build-specific GameMaker/native interface assumptions |
| `tools/qa_*.py`, window helpers | Bounded owned-session verification and evidence collection |
| `src/coop_ally.cpp`, `probe_yy.cpp` | Historical experiments; not the documented default |

The host game process owns the world. Both ships are real native Player instances
with independent Powers/build contexts. Hooks select the right owner for combat,
upgrades and HUD drawing. Shared XP schedules a native upgrade choice for each
ship. Ordinary choices use temporary owner-scoped native offer/confirm
transactions; no native UI828 instance survives a combat frame.
`ship_trays_runtime.hpp` owns tray state and input; `ship_coop_flow.hpp` and
`ship_coop_runtime.hpp` own zoom/revive policy and native integration.
This is not a custom network simulation: Remote Play streams the same
screen and forwards guest input to the host.

## Checks

Source-only Steam configuration fixtures:

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Windows launcher preference/argument checks use synthetic profiles:

```sh
python3 tools/test_launch_display.py
```

The live game tests launch bounded sessions and modify only owned profiles. Run
with the interactive game/helper closed:

```sh
python3 tools/qa_ships.py
python3 tools/qa_ships.py --presentation-controls
python3 tools/qa_ships.py --polish
python3 tools/qa_ships.py --upgrade-flow
python3 tools/qa_ships.py --trays
python3 tools/qa_ships.py --overlays
python3 tools/qa_ships.py --stock-hud
python3 tools/qa_ships.py --starter-bank
python3 tools/qa_ships.py --dual-controls
python3 tools/qa_ships.py --tray-controls --saved-controls
python3 tools/qa_ships.py --death-effects
python3 tools/qa_launcher.py
python3 tools/qa_launcher.py --remote-wrapper
NOVACOOP_TEST_RUNTIME=/path/to/isolated/runtime python3 tools/qa_bootstrap.py
```

`--remote-wrapper` simulates inherited app identity for a local process-chain
check; it is not a Steam connection test. Mutation modes in `qa_ships.py` should
fail their targeted ownership, native UI or input-sharing assertion. Review each
script's `--help` before using mutation or performance runs. Reports and captures
remain under ignored `local/`.

`qa_bootstrap.py` deliberately starts the run before module initialization has
finished. It uses the ordinary launcher with `qa_focus=0`, diagnostic logging
and fullscreen capture, without injecting QA commands. It checks two native
HUDs, both compact shops, middle-mouse/F7 closing and reopening, and actual J/L rotation and I
thrust while the shops are visible. A run that misses the early-start condition
fails rather than claiming coverage. Run it only against an isolated QA copy.

The portable control contract checks P2's three-button mapping, menu-down,
special actions, P1 braking and optional directional steering:

```sh
g++ -std=c++17 -Wall -Wextra -pedantic tools/three_button_controls_contract.cpp -o local/build/three_button_controls_contract
local/build/three_button_controls_contract
```

The upgrade-flow regression also has three expected failures:

```sh
python3 tools/qa_ships.py --upgrade-flow --mutation-startup
python3 tools/qa_ships.py --upgrade-flow --mutation-pause
python3 tools/qa_ships.py --upgrade-flow --mutation-healthfx
```

They restore the native starter menu, combined pause inventory, and old central
shield-flash coordinates respectively. Each must fail its corresponding check.

`--tray-controls` starts both ships from rest with both trays open, injects native
mouse and keyboard input, verifies thrust/steering/fire without spending points,
and checks deliberate purchases with mouse and Inspect+confirm. The negative
control `--tray-controls --mutation-tray-input` restores the old visible-tray
blocker and must fail the acceleration check.
`--tray-controls --mutation-tray-cursor` restores OS-pointer hit testing and must
fail the native cursor placement check. The mouse checks position the real native cursor as a QA fixture and inject
Windows button events; raw mouse-device movement is not reproduced by this
setup. Gameplay deliberately locks the OS pointer at window center. The suite temporarily enables native mouse aim
in the owned QA profile and restores the previous preference bytes afterward.

`--saved-controls` writes a P1 profile before starting the isolated client, covering
native input-field initialization during module loading.

`--death-effects` creates thrust effects through actual native ship input, then
downs each pilot while breaking their shield. It verifies effect cleanup,
survivor combat, preserved builds, beacon revival, restored Salvo firing and
the native end screen. Its proximity placement is an explicit QA fixture.
Run it with `--mutation-death-step` or `--mutation-thrust-cleanup` to restore
each original missing-player crash independently.

`tools/diagnose_display.ps1` passively reports physical client/monitor bounds for
an exact PID, creation time and EXE SHA. Monitor coverage proves fullscreen-sized
presentation; it cannot distinguish exclusive from borderless fullscreen alone.
Normal launches request native fullscreen and set only the isolated profile's
`windowedMode`/`borderlessWindow` keys, preserving other preference bytes. Bounded
QA defaults to `-inawindow`; explicit display arguments override that default.

Do not commit game files, copied SDKs/binaries, raw decompilation, saves, Steam
configuration, invitation links or private runtime logs. Dependency download
locations and SHA-256 pins belong in `dependencies.json`.

The balance integration suite is `python3 tools/qa_ships.py --balance`; use a
separate owned QA installation as described in [BALANCE.md](BALANCE.md).

`--overlays` uses Pillow and a foreground Windows game client to check actual
owner-colored native beacon artwork pixels, native upgrade-key/deferred requests for living
and downed ships, both compact strips, Inspect, and shared pause. It captures
only the verified game's client area. `--overlays --mutation-beacon` deliberately
hides the beacon and must fail the pixel assertion.

## Prebuilt release

Build the ship DLL, launcher/sandbox, control editor and Steam helper first.
`python3 tools/make_release.py --version VERSION` packages only explicit mod
artifacts and documentation under ignored `local/releases/`. The Windows
installer validates package/dependency checksums and the original game build,
rejects overlapping or unowned destinations, and patches only its owned copy.
After committing, `python3 tools/package_sources.py --version VERSION` adds
the committed project and pinned upstream source trees to a companion archive.
Upload the compiled ZIP, checksums and matching source archive to the same
GitHub release. Source archives must include the pinned Aurie, YYToolkit and
SDK source trees with their license notices.
